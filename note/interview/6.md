## 一、这一阶段做了什么（通俗版）

一句话：把「项目能跑、能检查、有一套统一的数据模型」落地，给后面的存储、协议、抓取三条线提供共同地基。

**1. 工程脚手架**

- `package.json`：ESM（`"type": "module"`），Node `>=24`，bin `coursework -> dist/cli.js`；运行时依赖 `commander` + `zod`，开发依赖 `typescript` + `vitest` + `@types/node`（决策 #35）。
- `tsconfig.json`：`strict` + `NodeNext`，`noEmit: true`，包含 `src`、`test`、`vitest.config.ts`。
- `tsconfig.build.json`：继承上面那份，关掉 `noEmit`、`rootDir: src`、只编译 `src` → `dist/`。也就是「检查」和「构建」用两份配置，避免把测试也编进发布产物。
- `src/cli.ts`：commander 入口，`coursework --version` 从 `package.json` 读版本并打印。

**2. 一条检查命令，三处共用**

- `npm run check` = `tsc --noEmit && vitest run`。
- `.claude/check.sh` 直接 exec 它（Stop hook 因此真正开始拦人）。
- `.github/workflows/ci.yml` 在 PR 和 push `main` 上跑 `npm ci && npm run check`，Node 24。
- 本地、hook、CI 完全同一条命令，避免「本地过、CI 不过」。

**3. 领域模型（`src/domain/schemas.ts`）**

- 用 zod 定义 9 个 schema：Module、Course、Assessment、SourceItem、Citation、Step、Task、Change、Run。
- TypeScript 类型不手写，全部 `z.infer` 从 schema 推导。
- 除字段类型外，把「跨字段不变式」写进 `superRefine`：
  - Task：`coursework` 的每个 step 必须有引文；`manual` 的 step 不能有引文；`repeat` 和 `due` 不能同时出现。
  - Change：`item.added` 只能有 `after`，`item.removed` 只能有 `before`，`*.changed` 两个都要有。
- `src/domain/course.ts` 单独放课程级校验：`assessmentsComplete === true` 时权重和必须为 100（带浮点容差，错误信息点名课程和实际和）、最多一个 final、每个 assessment 的 `courseId` 必须等于课程 id。

**4. 纯函数**

- `src/domain/progress.ts`：模块进度 = 完成步骤数 / 非重复任务的总步骤数；没有可计步骤时返回 `0`（不是 `NaN`）。
- `src/domain/grade.ts`：`projectGrade()` 只留 `TODO(human)`，函数体由你亲手写（决策 #34）；场景测试先写好、用 `describe.skip` 挂起。

**5. 测试与夹具**

- `test/` 按场景覆盖上面每条不变式；`test/fixtures/synthetic.ts` 全部是合成数据（假课程代码、`example.invalid`），真实课程数据不进仓库。

## 二、为什么这样做

- **为什么是 zod：** 一份定义同时给运行时校验和 TS 类型，避免「interface + 另一个 validator」两份定义漂移；M2 的协议和 MCP 还能直接从 schema 推 JSON Schema。替代方案是手写类型 + 手写校验器。
- **为什么是 Node 24：** 存储层已确定用 `node:sqlite`（#18），它需要较新的 Node；Node 24 LTS 类型剥离稳定，Playwright 官方支持 Node 而 Bun 不官方支持（#17）。所以脚手架阶段就把 `engines` 和 CI 都钉在 24，别等写存储时才发现跑不起来。
- **为什么权重和只在 `assessmentsComplete` 时查：** 学期中途课程可能只放出部分考核项，此时和不到 100 是正常的；把「列表是否已完整」显式建模成布尔字段，而不是让代码靠权重和去猜。替代方案是任何时候都要求 100，会让同步中途全部报错。
- **为什么重复任务不能有截止日期：** 重复任务用 `repeat` 表达节奏，再带一个 `due` 就会出现两个时间语义（#31 里每日重复在日历上汇总成一行）。替代方案是允许 `due` 但排程忽略，或另设字段区分——都会让「这个任务什么时候算到期」变模糊。
- **为什么 grade 留给用户：** 面试要能讲清自己写的核心业务逻辑（#34）；它是纯函数、有现成测试，不阻塞其他线。
- **为什么检查命令只写一条：** 单一事实来源同样适用于流程；hook 和 CI 共享 `npm run check`，规则不会两处漂移。先不上 lint，strict TS 已经挡掉大部分问题，之后加的成本很低。
